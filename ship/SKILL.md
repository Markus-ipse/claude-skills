---
name: ship
description: End-to-end shipping flow — /simplify cleanup, tests/lint/build, pre-commit review, visual verification, commit on a feature branch, PR, review comments, handoff. Invoke ONLY on explicit `/ship` or when the user asks for it by name — do not auto-trigger; "ship it" alone belongs to pre-commit-review.
---
1. If on the default branch (main or master), create a feature branch. Decide which files belong to this change; list anything that will be left unstaged, and ask if unsure. Unless none of those files is one the build or runtime executes or reads (pre-commit-review's routing test), clean up before staging: save `git diff HEAD` to a scratch file, run /simplify, and compare against the saved diff. /simplify scopes itself to the branch's commits plus *all* uncommitted changes, unrelated ones included, and edits the working tree — so if it touched anything outside this change (a file you're not staging, or untouched code in one you are), list those edits and ask whether to keep them; never revert a whole file. Stage only this change's files, including the cleanup you kept. Run the repo's test, lint, and build commands; if it has none, say so and continue. Stop on failure.
2. Run /pre-commit-review and fix every finding — when invoked from ship, skip its address-review handoff and apply fixes directly. Re-stage the fixed files after each round. Repeat at most 2 rounds. If any findings remain list them and ask the user whether to proceed. If anything was fixed, re-run test, lint, and build.
3. If UI changed, start the app if it isn't running (e.g. via /run), screenshot the affected view with chrome-devtools and confirm visually. If the browser is unavailable, state UNVERIFIED — in the PR body too.
4. Re-stage, then commit on the feature branch (never main or master) and push it with `git push -u origin <branch>`. Open a PR with a summary of changes + verification evidence — or, if one already exists for the branch, update its description instead.
5. Wait for CI with `gh pr checks --watch`, then poll for bot reviews for 10 more minutes. If CI is red, read the failing log, fix, push, and wait again — at most once; still red, stop and report. Then for every PR review comment, fix it and reply, or reply only. Commit and push any fixes, and wait for CI on the new head. Stop once CI is green on the latest push and every comment is answered — never merge; that is the user's call.
6. Run /handoff to write/update the brief (state, what shipped, the next ready item, and when PR comments were last checked). It lives in ~/.claude/handoffs/<repo>/<slug>.md, outside the code repo — never commit a handoff into the repo or its PR. Run this step even when an earlier step stopped the flow.
